## MODIFIED Requirements

### Requirement: Recovery phrase backup

The app SHALL display a 12-word recovery phrase in numbered order on the recovery-phrase screen, with backup-status indicators (Device/iCloud/Backend) and a warning that the phrase cannot be recovered by WDK. The phrase SHALL be generated by WDK before display (not read from static mock defaults). Confirming backup SHALL persist the wallet to secure storage and unlock the runtime before navigating to home.

#### Scenario: Recovery phrase renders all 12 words in order

- **WHEN** the recovery-phrase screen is shown during new-wallet onboarding
- **THEN** all 12 words from the WDK-generated mnemonic render in a numbered 2-column grid in their generated order

#### Scenario: Confirming backup enters the wallet

- **WHEN** the user taps "I've saved it — Continue"
- **THEN** the wallet is persisted through WDK, the runtime reaches ready (or equivalent unlocked state), the app navigates to the home screen, and the onboarding stack is not reachable via back navigation

#### Scenario: Phrase generation happens before display

- **WHEN** the user reaches the recovery-phrase screen from Wallet Setup
- **THEN** the app has already requested mnemonic generation from WDK and shows a loading or error state until words are available

## ADDED Requirements

### Requirement: Wallet setup hub after auth gates

After Google Sign-In and app biometry enrollment, when no wallet exists on device, the app SHALL present Wallet Setup with explicit create-new and restore paths.

#### Scenario: Create new wallet from setup

- **WHEN** the user taps create new wallet on Wallet Setup
- **THEN** the app navigates to the recovery-phrase screen to generate and display a new mnemonic

#### Scenario: Restore from setup

- **WHEN** the user taps restore with recovery phrase on Wallet Setup
- **THEN** the app navigates to the restore screen
